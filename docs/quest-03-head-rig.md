# Quest 03 first-person head rig

Stage 03 replaces the Stage 02 tabletop ring with a first-person robot-eye view in fully virtual OpenXR on top of merged PR #2 (`docs/quest-02-arena-menu.md`). It is not yet worn on a headset; Stage 01, Stage 02, and Stage 03 headset gates remain **pending**.

## Coordinate spaces

- **S0 (Sim):** `ArenaController` simulation metres (`ARENA_RULES`, `ARENA_LAYOUT`), unchanged. Phone AR and combat math are untouched.
- **S1 (Ring-local tabletop):** `fighterY = ARENA_LAYOUT.floorHeight + ARENA_LAYOUT.footOffset`. The player eye anchor `eyeRingLocal(anchor)` places `ROBOT_EYE_MODEL = [0, 1.1271, 0.2028]` (from `eye_l`/`eye_r` rest midpoint in both fighter GLBs) in the frozen player fighter frame, **ignoring `lift`** so hops/hits never move the camera.
- **S2 (VR metres):** `S1 * QUEST_WORLD_SCALE` (`QUEST_WORLD_SCALE = 16`, a reversible tuning constant). At `S = 16`, robot height is `~1.92 m`, eye height above the fighting floor is `~1.355 m`, spawn gap is `3.04 m`, and default eye-to-opponent center distance is `~2.80 m`.
- **S3 (OpenXR `LOCAL`):** Untouched native 6DoF scene root (`VROSceneRendererOpenXR`). No `<ViroCamera>`, no `ViroGameLoop` per-frame rig updates, no head bob, no hit shake, and no native `recenterTracking`.
- **S4 (Calibration frame):** `{ origin, yaw, posture, source, entry }` in S3 (`DEFAULT_CALIBRATION = { origin: [0, 0, 0], yaw: 180, posture: 'standing', source: 'default', entry: 0 }`), using the repo `facing` yaw convention (`0 = +Z`, `+90 = +X`, `180 = -Z`).
- **S5 (Gameplay head pose):** Output-only bounded offsets (`lateral`, `vertical`, `forward`, and `/ QUEST_WORLD_SCALE` in `sim`), `yawRelative`, `clamped`, `excess`, and `outOfBounds = excess > 0.30`.

## Rig hierarchy, calibration, and comfort decisions

- **Static horizon-locked rig:** `QuestRing` wraps S1 content in a 3-node `<ViroNode>` rig (`position={rig.position}` + Y-only `rotation={[0, rig.rotationY, 0]}` -> `scale={[16, 16, 16]}` -> `position={rig.contentOffset}`). The rig updates only on explicit calibration events (`calibrateForSolo`, `cyclePosture`) or Horizon system recenter events, never from per-frame head motion.
- **Own-body occlusion vs real asset lease:** `Mike_Player1_Blue_Combat_AR.glb` shares a single body mesh (`SKM_MegaMikeZ_part_0`) with eyes inside the visor, so the blue `Viro3DObject` stays mounted with `visible={false}` and retains its real `onLoadEnd`/`onError` callbacks. A stance floor ring marks the calibrated position and tints when `outOfBounds` is true. It is centered under the robot eyes (`stanceMarkerRingLocal(anchor)`), which the rig places on the calibrated head, not under the fighter's feet, which are `ROBOT_EYE_MODEL` z (`0.244 m` in VR) behind the eyes. Fighters, arena, and `QUEST_WORLD_SCALE` are unchanged.
- **Sample pipeline & lifecycle:** `ViroScene.onCameraTransformUpdate` writes validated samples (`headSampleFromViro`, rejecting non-finite/zero vectors and normalizing `forward`/`up`) into a 64-entry O(1) ring buffer; store subscribers and the scaled (`0.05`) diagnostics `ViroText` strip update at most 5 Hz, and `ReactNativeJS` logcat pose summaries log at most 1 Hz.
- **First-Solo-per-entry calibration vs Horizon system recenter:** Keyed to `questRuntime.getSnapshot().entries`. Horizon OS's built-in system recenter (long-press Meta button) rotates/shifts OpenXR `LOCAL` around the wearer (`XR_TYPE_EVENT_DATA_REFERENCE_SPACE_CHANGE_PENDING`), which already aligns the view direction and position natively. By contrast, in-app Solo calibration (`calibrateForSolo`) records the wearer's current eye height (`Y`), XZ origin, and yaw in S4 (`calibration.origin`, `calibration.yaw`) to align the 16x VR fighting ring's eye anchor and `QUEST_HEAD_BOUNDS` box when entering `Solo`, and `Back -> Solo` within the same entry preserves that ring anchor. There is no duplicate in-app `Recenter` button on the panel. `Posture` cycles `'standing' <-> 'seated'` and updates only `QUEST_HEAD_BOUNDS`:
  - `standing`: lateral `±0.30 m`, crouch `0.45 m`, rise `0.05 m`, forward/back `±0.20 m`
  - `seated`: lateral `±0.25 m`, crouch `0.25 m`, rise `0.05 m`, forward/back `±0.20 m`
- **Horizon system recenter handling (zero snap-back):** Prior behavior detected an abrupt `LOCAL` jump and called `rebaseCalibration`, which mathematically canceled Horizon OS's shift/turn and snapped the ring back to its old physical pose after ~6 frames. Instead, `tools/quest/viro-renderer/0002-openxr-quest-panel-layer.patch` records `XR_TYPE_EVENT_DATA_REFERENCE_SPACE_CHANGE_PENDING` in `VROSceneRendererOpenXR::pollEvents` and increments `quest_panel::bumpRefSpaceEpoch()` at `frameState.predictedDisplayTime >= changeTime` right before `xrLocateViews` (`QuestPanelModule.refSpaceEpoch()`), with consecutive raw-sample discontinuity detection (`isReferenceDiscontinuity`, `dt <= 100 ms`, `>= max(0.25 m, 4 m/s * dt)` or `>= max(45°, 900°/s * dt)`) as a fallback. On `default` (pre-Solo menu), content follows `LOCAL` directly so calibration stays `DEFAULT_CALIBRATION`. On an active calibrated ring, `acceptSystemRecenter` re-anchors `origin` and `yaw` (`source: 'system'`, keeping `posture` and `entry`) to the wearer's new pose in `LOCAL` so the Meta recenter takes effect smoothly without snapping back and `QUEST_HEAD_BOUNDS` re-centers at the new eye pose. The tracked camera is never driven, and `recenterTracking()` / second-session OpenXR APIs are never called.
- **Clean rounded compositor menu, HDR lighting, & packaged fonts:** `QuestMenu` renders via the OpenXR underlay compositor (`modules/quest-panel` + `tools/quest/viro-renderer/0002-openxr-quest-panel-layer.patch`) with vector ops + packaged `ArenaNotoSans.ttf` / `ArenaNotoSansSemibold.ttf` fonts (`QuestPanelModule` caches `Typeface.createFromFile` / `android_res` raw assets off the UI thread on `drawExecutor`, falling back cleanly if a custom font is unavailable without any PNG or loading screen). `QuestPanel` draws a single full-quad rounded `#0f172a` card (`QUEST_MENU_CARD_RADIUS_PX = 56`, no outer `#09090b` border), while `questMenuLayerMask` uses the matching rounded-rect SDF fragment shader (`QUEST_MENU_LAYER_MASK_FRAGMENT`) to `discard` corners outside the rounded rectangle so neither black skybox nor arena shows a dark border. `ViroXRSceneNavigator` keeps `hdrEnabled` on and `bloomEnabled={false}` so Viro runs PBR lighting and Hable tone mapping (`MI_ZMike_default` red/dark materials instead of un-tonemapped blown-out white Blinn fallback), while `0002` prepares the panel before eye rendering and sets OpenXR display `_clearAlpha` to `0.0f` when `questPanel` is active so `VROToneMappingRenderPass` preserves the zero-alpha hole cleanly. Input remains trigger-only (`questTriggerPress`/`questPointerHover`, gaze source 12 ignored) with a Viro `QuestMenuFocus` hover outline. Menu poses (`menu` at `[0, -0.08, -1.5]`, `ring` at `[0, -0.85, -1.35]`) and two-row layouts (`menu`: `Solo`, `Standing`/`Seated`, `Exit`; `ring`: `Ready`/`Set`, `Back`, `Standing`/`Seated`, `Exit`) stay synced frame-for-frame with hit targets.
